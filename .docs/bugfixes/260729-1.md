# 260729-1 — reliable4 prod-freeze primary fix

Root cause + reproducers: `.docs/reliable4/prod-freeze-pprof-diagnosis.md`,
`.docs/reliable4/freeze-fix-plan.md`. RED reproducer committed at 7373697.

- [x] BUG #1 — Unbounded per-job-change DB-write goroutine spawn (the freeze engine). `jobqueue/db.go` `launchJobChangeUpdate` and `launchJobExitUpdate` each do `go func(){ db.bolt.Batch(...) }` — one unbounded goroutine per job state change/exit. A big un-suspend flips ~100k jobs at once → ~100k goroutines pile up in `bbolt.(*DB).Batch`, coalescing collapses to thousands of tiny fsync'd txns on the single write lock, the synchronous `archiveJob` commit is starved past the 60s client floor → churn. FIX: a bounded, coalescing, dedup-by-`Job.Key()` single writer goroutine that folds ALL pending ops into ONE `db.Update` per cycle. RED test `jobqueue/reliable4_writestorm_test.go` (`TestReliable4WriteStormGoroutineExplosion` + `…ExitExplosion`) must go GREEN (added 5006→≤512) with the latest-wins persistence assertion still passing. Constraints in freeze-fix-plan.md §"Fix 1 implementation constraints" (fold-into-one-Update; dedup latest-wins; keep archive-vs-change guard; exit side-effects + `updatingAfterJobExit` decrement; no backpressure under `wgMutex`/`db.Lock`; keep `db.wg` tracking + close()-drain; set `backupDirty`).
  - `jobqueue/db.go`: added a single long-lived `bestEffortWriter` goroutine (started in `initDB`, stopped+final-drained by `close()` via `finaliseBackup`→`stopBestEffortWriter`, unconditionally). Pending state under a new leaf mutex `beMu`: `beChanges map[string][]byte` (coalesce by key, latest-wins), `beExits []jobExitData` (ordered, side effects preserved), `beWGKeys []string`; buffered(1) `beSignal` kick + `beStop`/`beWriterDone` lifecycle. `launchJobChange/ExitUpdate` now enqueue non-blockingly (never block under `db.wgMutex`/`db.Lock`); the writer folds all pending into ONE `db.Update` per drain (`beBatch.apply` = `applyChanges` w/ the archive-vs-change guard, then ordered `applyExits`). Changed `updatingAfterJobExit int`→`atomic.Int64` so the writer's exit decrement needs no `db.Lock` (deadlock-free); `waitForJobExitUpdates` now a lock-free poll.
  - New `jobqueue/reliable4_besteffort_writer_test.go`: `TestReliable4BestEffortCoalesces` (4000 change-updates to 4 keys → 8 bolt write-ops, latest-wins) + `TestReliable4BestEffortCloseDrains` (close() drains, no loss/hang).
  - RED reproducer `TestReliable4WriteStorm{Goroutine,Exit}Explosion` now GREEN (added 5006→1). `make test` PASS, `make lint` 0 issues, `go build` PASS, `-race` 0 data races. Reviewer PASS (independent stash-control). `make race` test-failures are a pre-existing TTR/-race-oversubscription flake (same fixed binary passes in isolation; DB-write path can't influence the in-memory kill/bury timing). Scale gate `wrdev.sh unsuspend-burst` re-run post-fix to confirm peak bw stays low (pre-fix 57,053).

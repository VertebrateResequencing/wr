# gosec's G703 taint finding on test helpers is unstable, and has cost three fixes

- [ ] `gosec`'s `G703: Path traversal via taint analysis` fires and stops firing
      on `jobqueue/lost_job_behaviours_test.go:594` depending on unrelated
      changes elsewhere in the package. It has been worked around three
      different ways in three PRs. The repo wants one decision, not a fourth
      workaround.

## The three workarounds so far

| PR | What was done | Why it stopped working |
| --- | --- | --- |
| #577 | Split `if _, err := os.Stat(path); ...` into two statements | Held for that PR only |
| #578 | `//nolint:gosec // test-controlled path under a temp dir` | Needed again on a different set of lines |
| #579 | `os.Stat(filepath.Clean(path))` | Current; satisfies gosec with no directive |

## The instability, measured

On the `remove-hold-file` branch, in one sitting:

1. `make lint` reported it, alongside an unrelated `errcheck` finding.
2. Fixing only the `errcheck` finding made **gosec stop firing** - at which point
   `nolintlint` reported the `//nolint:gosec` directive as **unused**, which is
   itself an error, so the directive had to be removed.
3. It then **fired again** after a change to a Go **comment** and a markdown
   file - nothing that can alter data flow.
4. It reproduces after `golangci-lint cache clean`, so it is **not** a caching
   artefact.

`gosec`'s taint analysis is inter-procedural, so what it can trace depends on
the whole package's call graph, and apparently on more than that.

## Why a `nolint` is not the answer

`.golangci.yml` gives `nolintlint` no configuration, so it runs with defaults and
an **unused** directive is reported as an issue. Combined with the flicker above,
a suppression fails in **both** directions: it is an error when the finding is
absent, and required when it is present. There is no stable state for a
directive on this line.

## Options, for whoever decides

1. **Keep fixing the code** so gosec has nothing to say, as #579 does with
   `filepath.Clean`. Cheapest per instance, but it is three instances now and
   each is a small unexplained-looking change in a test.
2. **Exclude `gosec` for `_test.go`** in `.golangci.yml`. The existing
   `exclusions.rules` block already excludes `contextcheck`, `cyclop`, `funlen`,
   `gocognit`, `gocyclo`, `maintidx` and `revive` for `path: _test\.go`, so the
   precedent and the mechanism are there. gosec's threat model - untrusted input
   reaching a filesystem call - does not describe a test building paths under
   `t.TempDir()`. **Cost:** it would also hide any genuine gosec finding in test
   code.
3. **Set `nolintlint`'s `allow-unused: true`**, which would make a suppression
   stable. **Cost:** dead directives stop being reported repo-wide.

My own view, unmeasured: option 2 scoped to `G703` alone if golangci-lint allows
a rule-level exclusion, since the false positives all share that one rule.

## Not a defect in any change

Every instance has been a test helper acting on a path the test itself created
under `t.TempDir()`. No production code path is implicated, and no reported
instance has been a real vulnerability.

- [x] jobqueue.Connect's timeout does not bound the dial or the TLS/SP handshake. internal/mangostlstcp/tlstcp.go uses `&net.Dialer{}` with no timeout (:703) and `tlsDialer.DialContext(context.Background(), ...)` (:370). A server that accepts TCP but then stalls, as a frozen manager's kernel accept backlog does, makes Connect (and so any `wr` command, or a runner) hang indefinitely instead of failing after its timeout.   - Fix: internal/mangostlstcp/tlstcp.go gains a transport option, `OptionHandshakeTimeout` (a `time.Duration`, default `DefaultHandshakeTimeout` = 30s when unset or not positive), accepted by both the dialer and the listener. The dialer's `Dial` takes one deadline from it and applies it to the TCP connect and TLS handshake (`tls.Dialer.DialContext` with a deadline context) and to the SP handshake. `connPipe` now carries that deadline, and `handshake()` sets it on the conn before exchanging headers and clears it once they validate, so an established pipe has no deadline left on it. mangos's background redials call the same `Dial`, so they are bounded too. The listener gives each accepted connection a deadline of accept time plus its timeout, so a client that connects and never handshakes is dropped instead of pinning a handshaker goroutine and its fd forever. This was the same small change, so it is fixed here rather than recorded separately.
  - jobqueue/client.go: `dialClientSocket` passes Connect's `timeout` as `OptionHandshakeTimeout`, so Connect returns `ErrNoServer` about `timeout` after dialling a stalled server, as for other unreachable cases. Connecting to a port nothing listens on still fails at once (connection refused), and the Ping and the send and receive deadlines are unchanged. The subscription socket (jobqueue/subscription.go) gets the 30s default; only a comment there changed, the one saying its dial had no timeout of its own.
  - Tests: jobqueue/client_connect_test.go `TestConnectToStalledServerFailsPromptly` (replaces the zz_ harness). A listener accepts TCP and holds connections silently. Connect with a 1s timeout must return within 5s with `ErrNoServer`, and Connect to a closed port must fail in under 1s with `ErrNoServer`. New internal/mangostlstcp/tlstcp_test.go `TestHandshakeTimeout`: with a 300ms timeout, a listener closes a raw TCP client that never handshakes well before a 3.3s limit. A req/rep pair that has handshaked still exchanges messages after twice the timeout, with redial disabled so a replaced connection can't hide a dead one. Mutation checks: not setting the handshake deadline fails the first case (read ended on the test's own deadline), and not clearing it fails the second (`send time out`).

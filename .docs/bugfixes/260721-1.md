# Bugfixes 260721-1

- [x] This branch's changes have re-introduced a bug that complete jobs (or at least fully complete repgrps?) are not supposed to re-appear in the web UI after a page refresh. Use /bugfix to fix
  - Root cause: Phase 2 D1 (this branch) replaced the old `statusState` projection with the slim `repGroupCounts` (`jobqueue/repgroupcounts.go`), whose `subscribe()` seeded a fresh web client via `wholeMapLocked()` — the whole map INCLUDING terminal-only (complete/deleted) RepGroups. So a page refresh (a fresh status subscriber) re-showed complete-only RepGroups. Third regression of a twice-fixed behaviour (260626-2, 260716-1); the reliable2 spec's D1 wording explicitly (and wrongly) mandated seeding the whole map.
  - Fix (`jobqueue/repgroupcounts.go`): added `liveSeedLocked()`/`rgcSeedCountCopy()`/`rgcHasLiveJob()` (faithful ports of the old `statusstate.go` `liveSeedLocked`/`seedCountCopy`/`hasLiveJob`; live = state != Complete && != Deleted with positive count); `subscribe()` now captures the filtered seed (include a RepGroup only if it has >=1 live job; send live states + `complete`; strip `deleted`; omit complete-only/deleted-only RepGroups) under the same lock that registers the subscriber. `wholeMap()`/`wholeMapLocked()` KEPT (still include terminal) to back the `+all+` aggregate and the live per-RepGroup push, so a RepGroup completing WHILE connected stays visible (260625-6 not regressed). Only the fresh-connect seed VIEW is filtered — reliability invariants A1/B1/C1 untouched.
  - Tests: flipped `TestRepGroupCountsSeedIncludesTerminal` -> `TestRepGroupCountsSeedOmitsTerminal` (complete-only RepGroup ABSENT from fresh seed; `wholeMap()` still tracks it); added `TestRepGroupCountsSeedFilter` (live RepGroup seeded live+complete no deleted; complete-only/deleted-only omitted; completing-while-connected stays visible); restored `TestHighPressureCompletedRepGroupStatusSurvivesRefresh` fresh-reconnect assertion to ABSENT (`readRepGroupAbsentDuring`), keeping its live/in-session/CLI-search assertions. TDD red->green confirmed (oracle: revert seed to `wholeMapLocked` -> new tests fail).
  - Docs: corrected `.docs/reliable2/spec.md` (D1) and `.docs/reliable2/phases/phase2.md` (Item 2.1) to describe the filtered seed, reversing the erroneous original D1 wording per this fix / 260626-2 / 260716-1.
  - Verified: `make lint` 0 issues; targeted `-race` (`TestRepGroupCounts|TestHighPressureCompletedRepGroupStatusSurvivesRefresh|TestReliable2|TestStatus|TestServerWebI|TestSubscription`) green, 0 races; `make browser-test` fixtures `completed-repgroup-visibility` + `removed-jobs-refresh` pass (pre-existing pure-JS `repgroup-bar-flicker` failure is not a regression).

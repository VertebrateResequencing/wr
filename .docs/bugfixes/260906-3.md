# Bugfixes 260906-3

- [x] wr pins `github.com/VertebrateResequencing/muxfys/v5 v5.0.0`, which loses
  data: `muxfys.Unmount()` uploads the cache and then deletes the cache
  directory without checking whether the upload succeeded. For a writable
  mount in CacheData mode that cache holds the only copy of everything the job
  wrote, so a failed upload destroyed the job's output. muxfys v5.1.0 fixes
  it: the cache directory that still holds un-uploaded files is kept, and the
  returned error names it. Update the dependency to v5.1.0 so wr users get the
  fix.
  - Not a bug in wr's own code, so there is no failing wr test to make pass.

  delete-the-cache-regardless behaviour, and the bump above makes them false.

      a specific CacheDir but CacheData was true, the CacheDir will be deleted.
      The exception is when files fail to upload: their only copy is the one in

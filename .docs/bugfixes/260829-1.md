- [x] Copilot suppressed comment on `jobqueue/utils.go:892` (PR #558, review 5056905598 of head 0c877ab): `rmCheckedEmptyDirs` detects the "directory is not empty" case with `strings.Contains(err.Error(), "directory not empty")`. Valid, and the code already admits it — the line above reads `// *** not sure where the "directory not empty" string comes from; probably not cross platform!`. Matching on a message rather than the errno means a system whose text differs turns an expected, benign "stop walking here" into a returned error. Consequence is a spurious `errNotBelowBaseDir`-style failure surfacing in `Execute`'s "Behaviour problems" stderr or a server-side `clog.Warn`, not data loss — the deletion simply stops. In scope because this branch restructured that function (LAYERs 2, 5 and 8 moved it from `rmEmptyDirs` into `rmCheckedEmptyDirs` and changed its signature), so it is in the PR diff.
  - Source: PR #558, review `5056905598`, suppressed comment (no thread to resolve).
  - Red command: none available on this platform — Go's syscall error strings are stable and English, so the current code is correct on Linux and the defect is a portability/robustness one with no behavioural red here. Per testing-principles that means no new behavioural test is invented for the errno change itself; the existing `TestRmEmptyDirs` "stop at first non-empty parent" case pins the behaviour that must not change, and a new assertion should pin that detection is by errno rather than by message.
  - Fix: new `errIsDirNotEmpty(err)` in jobqueue/utils.go using `errors.Is(err, syscall.ENOTEMPTY) || errors.Is(err, syscall.EEXIST)` (Linux reports ENOTEMPTY; POSIX allows EEXIST), replacing the substring match and deleting the `***` comment. `syscall` was already imported elsewhere in the package (client.go, server.go, memory_attribution.go) and `errors.Is(err, syscall.<ERRNO>)` is the repo's existing idiom (cmd/manager.go:945, jobqueue/scheduler/scheduler_test.go:323, network/port/port_test.go:71). The predicate is a named helper rather than an inline expression so the test asserts the same code production uses, not a copy of it.
  - Test: a Convey case in `TestRmEmptyDirs` — a non-empty leaf survives and no error is returned — with a nested assertion that the real OS error satisfies `errIsDirNotEmpty`. It has teeth: narrowing the predicate to EEXIST alone fails it with `Expected: nil / Actual: 'remove .../unique: directory not empty'`, confirming Linux returns ENOTEMPTY. What it does NOT prove, stated honestly: nothing about darwin/windows/BSD errnos, which no test here can exercise, and nothing about errno-vs-message on Linux, where both are correct — it is a tripwire against a future platform change.
  - Portability checked directly: `GOOS=darwin go build ./jobqueue/` passes; `GOOS=windows` fails **identically before and after** the change (go-fuse needs `syscall.Stat_t`/`Iovec`/`Flock_t`/`O_DIRECTORY`, and jobqueue/scheduler/local.go:1157 uses `Setpgid`), so it is pre-existing and was not touched. The new expression itself was compiled for windows, darwin, linux and freebsd in a scratch module — both constants exist in `syscall` on all four.

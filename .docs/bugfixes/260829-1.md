# Bugfixes 260829-1

Follow-up branch to PR #557. Carries the hardening of #557's BUG 12 and the two
flaky tests left open on PR #558, so that neither holds up the data-loss fix.

- [x] BUG 12 HARDENING: #557 fixed the `--runnermode`/`--servermode` children
  running most of the test suite by passing `-test.run` on each child's cmdline,
  at all four call sites. That restores the pattern the suite already used, but it
  is a rule a fifth call site can forget - which is exactly how the bug arose: two
  of the four call sites had it, and the two added later did not.
  - Consequence when forgotten: the child is a copy of the test binary, so it runs
    every test that does not itself guard on the mode. Those tests start managers,
    and `jobqueueTestInit` only isolates ports and the manager dir when NOT in one
    of these modes, so those managers take the default config - the user's real
    manager port, 5023. One child was measured holding 16498 sockets on it.
  - Fix: `dispatchSubprocessMode()` (jobqueue/subprocess_mode_test.go) does the
    runner/server work and exits the process before any test can run. `TestMain`
    calls it in both builds - the `!race` build gains a `TestMain`, and the
    existing `race` one (which already existed, to clean up its compiled binary)
    calls it first. One `TestMain` per package, hence the shared function.
  - The `-test.run` flag is deliberately KEPT as a second layer: each child's
    cmdline must stay consistent because crash recovery matches a recovered runner
    by its exact cmdline. The point of this change is that the guarantee no longer
    depends on remembering it.
  - Red/green, by simulating the forgotten call site: with
    `runnerModeTestRun` neutered to `""`, `go test -run TestJobqueueRunnerScheduling`
    on develop (no TestMain dispatch) peaks at **16498** sockets on :5023 and takes
    **119.6s**; on this branch it peaks at **0** and takes **9.1s**. Restored
    byte-exact afterwards, md5 `9aa80fa4b59c9b8f766523de0033a6c8`.
  - `TestJobqueueRunnerModeEntrypoint` no longer performs the dispatch (TestMain
    exits first, so its old body was unreachable). Rather than delete it and leave
    `runnerModeTestRun` naming a test that does not exist, it now asserts the
    invariant TestMain enforces - `runnermode` and `servermode` are both false by
    the time any test runs - so the dead code became the regression test for this
    fix. The now-unreachable `servermode` branch of `TestJobqueueSignal` is removed.
  - Gates: `make test` `359 passed / 9 skipped / 3m23s`, `make lint` `0 issues.`

# Bugfix checklist 260726-3 — reliable4 TTR-miss archive-reject churn (runner-pid liveness)

Full analysis + recommendation: `.docs/reliable4/ttrmiss.md`. A validated,
ENV-GATED prototype was committed at 39f9afc; this makes it the DEFAULT (removes
the `WR_EXP_*` gating), turns the backstop into a real config value, fixes a
forced-command compatibility bug in the kill path, and adds regression tests that
run in `make test`. Deterministic reproducer (build tag `reliability_repro`,
`developers/wrdev.sh ttrmiss-check`): `jobqueue/reliable4_ttrmiss_test.go`.

- [x] A job whose command SUCCEEDED but whose runner process is slow/starved (NFS writeback contention) or wedged before it can Archive() can be falsely marked lost -> confirmed dead -> re-run -> its real (late) archive rejected as "bad job" (ErrBadJob), so the success is discarded and a rerun is wasted. Root cause: the runner reports the COMMAND child's pid via Started (cmd.Process.Pid), which is dead as soon as the command finishes; the manager's confirmJobDead only checks that pid, so a completed-but-not-yet-archived job is condemned whenever the runner's touches lapse past the 60s TTR.
  - Root cause: the runner reports the command child's pid via Started (dead as soon as the command finishes), not its own; confirmJobDead condemned completed-but-not-yet-archived jobs whenever touches lapsed past the 60s TTR.
  - PART 1 (jobqueue/server.go confirmJobDead): now default-checks BOTH pids — a job is dead only if the command pid is gone AND (when a runner pid was recorded, runnerPid>0) the runner pid is also gone; runnerPid==0 (pre-upgrade records) falls back to the old command-pid-only behaviour. Removed the WR_EXP_RUNNERPID gate. (The Job.RunnerPid field + client os.Getpid() reporting + server recording landed earlier in prototype commit 39f9afc.)
  - PART 2 (jobqueue/server.go): wedged-runner kill backstop is now default-on with a real config value — ServerLostRunnerBackstop defaulting to 1h, exposed as ServerTimings.LostRunnerBackstop (test-overridable, withDefaults-wired), matching the ServerItemTTR/LostJobCheck* idiom. Removed WR_EXP_LOSTBACKSTOP_MS and lostBackstopDuration. backstopKillWedgedRunner force-kills the runner then lets the normal dead->retry path re-run it.
  - PART 3 (jobqueue/scheduler/scheduler.go): KillProcessOnHost now sends `kill -9 <pid> 2>/dev/null || true # wr-kill -p <pid>` (killProcessCommand helper) so an updated authorized_keys forced command can recognise+extract it; on the old ps-only forced command it degrades to a harmless no-op ps (safe, no regression). Added a CONTRACT WARNING mirroring ProcessNotRunningOnHost.
  - PART 4 docs: cmd/conf.go privatekeypath docs gain the updated forced-command example enabling the backstop kill (ps-only example + CONTRACT kept intact), with the tradeoff + login-user/no-injection reassurance; .docs/reliable4/ttrmiss.md STATUS updated; developers/wrdev.sh ttrmiss-check knob cleanup.
  - Tests (run in make test): TestReliable4RunnerPidLiveness + TestReliable4LostRunnerBackstop (jobqueue/reliable4_runnerpid_test.go) and TestKillProcessCommandContract (jobqueue/scheduler/process_test.go) — each verified RED pre-fix / GREEN post-fix. make test: 359 passed, 9 skipped. make lint: 0 issues.

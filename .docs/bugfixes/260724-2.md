- [x] §2b + §2a-priority: rac limit-group accounting. (§2b) A single scheduler group's runner `count` can exceed its limit group's limit because `accountForRunningJobs` (jobqueue/server.go) adds ALL run-sub-queue jobs of the group on top of a ready count that was capped at a SEPARATE, earlier limiter-capacity read — non-atomic, so reserves landing in between push count over the limit (reproducer `wrdev.sh overcount-check` → finalCount=3500 for a 2000 limit). Fix BOTH off one consistent per-limit-group read: allocate the ready budget preferring higher-priority groups, and cap each group's final (ready+running) count so the summed request for a limit group never exceeds its remaining capacity.

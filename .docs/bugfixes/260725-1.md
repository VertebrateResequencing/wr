This (a) makes the manager perpetually spawn useless empty-group runners that exit having run 0 commands, and (b) starves genuinely-ready jobs in the real group of runners: because the running jobs aren't counted into their real group, the group's runner request stays at ready-count only, and LSF's checkCmd (counting surviving pre-crash runner jobs) makes stillNeeded <= 0, so no new runner is ever submitted and the ready jobs stay pending forever.

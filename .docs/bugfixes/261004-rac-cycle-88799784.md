## Not taken

- A1, reordering `Job`'s fields so the snapshot's fields share one cache
  line, and C1, a prefetch pass over each batch of ready jobs before taking
  their read locks: rejected as fragile. Both depend on the allocator's size
  class and field offsets, which any later `Job` field change silently
  undoes, and C1 adds lock-free reads whose safety rests on `jobDerived`
  never being modified once stored.
- The investigation's B options: rejected for their risk (owner decision,
  261004), since only changes with no downside were to be taken.

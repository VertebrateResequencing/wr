# 260729-2 — reliable4 confirm-dead SSH connection leak (Fix 5, leak-fix scope)

Root cause + reproducer: `.docs/reliable4/freeze-fix-plan.md` Fix 5. RED repro
committed `b364c46`. This checklist is the LEAK FIX (close connections after the
check); the host-grouping coordinator (reuse one connection per host) is a larger,
review-worthy follow-up recorded in the plan doc, out of scope here.

- [x] Confirm-dead SSH connection leak. `Scheduler.ProcessNotRunningOnHost` (`jobqueue/scheduler/scheduler.go:625`) and `KillProcessOnHost` do `getHost` → (LSF) `cloud.NewServer` (a FRESH server) → `RunCmd`, which dials an `ssh.Client` and closes only the SESSION. The `Host` interface (`scheduler.go:327`) has no `Close()`, and the throwaway `cloud.Server` is never `Destroy()`ed, so the dialed client (its goroutines + socket) is NEVER closed — a per-check leak; `confirmJobDead` does 2 checks per lost job (prod: confirm-dead ssh conns 892→~5,300, ~31,875 goroutines). FIX: add `Close()` to the scheduler `Host` interface and close the host connection after each confirm-dead check (both `ProcessNotRunningOnHost` and `KillProcessOnHost`). LSF's throwaway server must actually close its ssh client(s); OpenStack's `getHost` returns a CACHED, shared `*cloud.Server` reused for real cloud ops, so its `Close()` must be a NO-OP (do not close the shared cached client — that would regress cloud server reuse); mock/local `Close()` no-op. RED repro `jobqueue/scheduler/reliable4_confirmdead_leak_test.go` (240 leaked ssh goroutines / 40 checks, bound 20) must go GREEN.
  - `cloud/server.go`: new `CloseSSHConnections(ctx)` (locks mutex, closes the dialed ssh client(s) via `closeSSHClients`, resets `sshClients`/`sshClientSessions`/`sshStarted` → idempotent, safe when nothing dialed, NO VM/provider teardown) + a no-op `Close(ctx)` so a plain `*cloud.Server` satisfies the extended `Host` (used by the cached OpenStack path).
  - `jobqueue/scheduler/scheduler.go`: added `Close(ctx)` to the `Host` interface + `defer host.Close(ctx)` in `ProcessNotRunningOnHost` and `KillProcessOnHost` (after the getHost-ok guard, before RunCmd → fires on every path including RunCmd errors).
  - `jobqueue/scheduler/lsf.go`: `lsfHost` wrapper whose `Close` calls `CloseSSHConnections` on the throwaway server (the leak fix); `getHost` returns it. `openstack.go` unchanged → its cached shared server's `Close` is the `*cloud.Server` no-op (cache reuse preserved). `local.go`/`mock.go`: no-op `Close`.
  - Tests: `cloud/cloud_test.go` `TestServerCloseSSHConnections` (idempotent/no-panic/state-reset, no ssh needed); `jobqueue/scheduler/process_test.go` `TestConfirmDeadClosesHost` (Close called exactly once per check, incl. RunCmd-error path + KillProcessOnHost). Both untagged (run in `make test`).
  - RESULT: RED repro GREEN (leaked 240→4, bound 20). `make test` PASS (all pkgs), `make race` PASS (0 data races, no failures), `make lint` 0 issues, `go build` clean. Reviewer PASS (independently verified OpenStack cached server is NOT closed). Scope note: this is the LEAK fix; the host-grouping coordinator (one connection per host for all its checks — a storm-load win) remains a recommended follow-up in `.docs/reliable4/freeze-fix-plan.md` (needs review: larger lost-job-path refactor).

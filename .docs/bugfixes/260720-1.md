# Bugfixes 260720-1

- [x] `queues_avoid` (Requirements.Other["scheduler_queues_avoid"]) is intermittently NOT honored once the manager has LEARNED resource recommendations for a job's ReqGroup, so LSF runners get submitted to a queue that should be avoided (e.g. cpu-interactive / *inference*), or jobs fail to schedule. On a FRESH db (no learned recommendations) it always works; the trigger is the recommendation path. Suspected NON-DETERMINISTIC / intermittent — "random based on map behaviour" (Go map iteration order or a map data race). Client path: client.New(SchedulerSettings{QueuesAvoid:"interactive,inference"}) with no explicit Queue; client.determineOverrideAndReq sets req.Other["scheduler_queues_avoid"] but NOT req.OtherSet=true. Server path: readyAddedCallback -> buildSchedulerGroups -> processReadyJob -> recommendedReqForGroup (builds Requirements with RAM/Disk/Time, NO Other) -> updateJobRequirementsForRetry -> applyRecommendedJobRequirements (RAM/Disk/Time only) -> schedulerGroupSnapshot -> reqForScheduler -> sgroup.req -> scheduler.Schedule -> lsf.determineQueue reads req.Other["scheduler_queues_avoid"]. Reproduce FIRST via an in-process test that learns a recommendation for a reqGroup, adds a job with scheduler_queues_avoid in Other (OtherSet=false), drives scheduling, and asserts the req reaching the scheduler still contains scheduler_queues_avoid / never picks an avoided queue; run under -race and high -count to surface map-order/race intermittency. MUST have a failing test before any fix; if not reproducible in current code after a thorough attempt (map-order, -race, concurrency, createJobs/inputToQueuedJobs, add-path per-reqGroup handling), report "cannot reproduce" with evidence rather than fabricating a fix.
  - Root cause (matches the "map behaviour" hint; NOT the server/recommendation
    path, which was verified clean): `client.determineOverrideAndReq` mutated and
    returned the caller's own `*Requirements`/`Other` map. Callers that share one
    `req` across `NewJob()` calls aliased a single Requirements+Other map, and
    concurrent `NewJob()` raced on `req.Other` (data race + concurrent map write),
    non-deterministically dropping `scheduler_queues_avoid` before serialization
    → LSF submits to an avoided queue.
  - Fix: `client/client.go` `determineOverrideAndReq` now clones the caller's req
    (deep-copying `Other`) before adding scheduler keys, and sets `OtherSet=true`
    when populating `Other`. Same requirement VALUES as before (behaviour-
    preserving for scheduling); each returned Job gets an independent
    Requirements+Other so shared/concurrent callers can't race or alias.
  - Tests: `client/client_test.go` adds `TestSchedulerNewJobDoesNotAliasCallerReq`
    (deterministic aliasing) and `TestSchedulerNewJobSharedReqConcurrent` (fails
    under `-race` with "concurrent map writes" on unfixed code), plus
    `TestSchedulerNewJobQueuesAvoid`; `jobqueue/queues_avoid_scheduling_test.go`
    adds server-side guards proving the scheduler/recommendation path preserves
    queues_avoid. Reviewer PASS: both new client tests fail without the fix and
    pass with it under `-race -count`; `make lint` 0 issues; `./client` `-race`
    green; no prior regression test weakened.
